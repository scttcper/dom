# Architecture

ctrl-dom (published as `@ctrl/dom`, https://github.com/scttcper/dom) is a DOM plus the Testing
Library stack, for testing React components on Node.js:

```
@ctrl/dom/react               drop-in for @testing-library/react           render, act, renderHook, cleanup
@ctrl/dom/user-event          drop-in for @testing-library/user-event      pointer/keyboard simulation
@ctrl/dom/jest-dom            drop-in for @testing-library/jest-dom        matchers for vitest/jest
@ctrl/dom/testing-library     drop-in for @testing-library/dom             queries, waitFor, fireEvent, prettyDOM
@ctrl/dom/aria                replaces aria-query + dom-accessibility-api  roles, names, states, hidden
@ctrl/dom                     replaces jsdom / happy-dom                   nodes, parser, selectors, css, events, window
@ctrl/dom/vitest-environment  installs the DOM as Vitest's test globals (@ctrl/dom-jest-environment: Jest's)
@ctrl/dom/register            the same for node:test / bun test (no environment)
@ctrl/sentry-tests            test runs in Sentry for Vitest and Jest, any DOM (its own package)
bench/                        benchmarks vs jsdom and happy-dom
```

Each lives in `packages/<name>/`, and code, tests, bench and downstream runners import them by
their published names: the root `package.json` is `@ctrl/dom` inside the workspace, its `exports`
sending each subpath to a member's sources (`packages/react` is `@ctrl/dom/react`). The Jest
environment and the Sentry reporter are packages of their own, `@ctrl/dom-jest-environment` and
`@ctrl/sentry-tests`.

The upper layers are allowed (and expected) to reach into `@ctrl/dom/internal` instead of
going through the public DOM API. That is the point of consolidating: `getByRole` walks
`NodeImpl` records, computes roles with an integer `switch`, and asks the CSS layer
"is this element display:none?" through a direct function with a per-node cache, instead of
calling `querySelectorAll('*')` + `getComputedStyle()` per element through generic APIs.

The DOM must ALSO be good enough that the stock `@testing-library/*` packages run on it
unmodified (people will swap only the environment first). `bench/` runs both stacks.

## Packaging

What ships is assembled by `pnpm build` (scripts/release.ts) into `release/`:

- `@ctrl/dom`: `@ctrl/dom` at the root and every other runtime package under a subpath
  (`@ctrl/dom/aria`, `/testing-library`, `/react`, `/user-event`, `/jest-dom`,
  `/vitest-environment`, `/register`), plus the Vitest plugin (`@ctrl/dom/vitest`,
  packages/vitest-environment/src/plugin.ts), the `ctrl-dom` bin (packages/cli) and a Jest preset
  generated by the assembly. publish/ holds only static files: READMEs and manifest templates.
- `@ctrl/dom-jest-environment`: `@ctrl/dom-jest-environment`, a package of its own so Vitest users do not
  install Jest's dependencies.

Every published package is under `@ctrl`. Vitest gets no environment package: it looks a custom
environment name up only as an unscoped `vitest-environment-<name>` package, so the `ctrlDom()`
plugin loads the environment by path and answers for the name "ctrl-dom" itself (per-file
docblocks).

Each workspace bundle keeps cross-package imports as bare specifiers (scripts/build.ts), and the
assembly rewrites them to published ones (`@ctrl/dom/aria` → `@ctrl/dom/aria`): inside `@ctrl/dom` they
are self-references, so every internal package exists once. `@ctrl/dom` and `@ctrl/dom/internal`
resolve to generated bridges that return the DOM instance the running environment published on
the test global, so test code and the bundles share it even where a test file's modules are
evaluated in a vm context (Jest, Vitest's VM pools); with no environment they load the DOM.
`pnpm test:pack` installs the three tarballs into a fresh project and runs every documented
setup against them.

The three packages are versioned independently by semantic-release (`tools/release`, run by
.github/workflows/release.yml): each one's commits are the conventional commits that touch the
paths it is built from (tools/release/packages.ts), and the environments peer-depend on
`^<latest @ctrl/dom>`. Versions live in git tags and on npm; nothing is committed back.

## Why not native code?

The DOM is plain TypeScript run by V8, and that was measured, not assumed. A compiled library
called through Node-API (tried with scriptc, Node 26.12) costs ~12–14 ns per call against well
under 1 ns for an inlined JS call, copies and transcodes every string that crosses, and was not
faster than V8's JIT on DOM-shaped work. React touches the DOM through millions of tiny calls
(`createElement`, `setAttribute`, `appendChild`, property reads), and every node must be a JS
object anyway (React stores fibers and props as expando properties on it), so a node store
behind a native boundary makes the hot path slower; the author's earlier native DOM
(`~/gh/vibedom`) reached only rough parity with happy-dom for that reason.

The pure parsers (HTML tokenizer, CSS tokenizer and parser, selector parser, entity decoding)
were the best case for native code, since one call does a lot of work. Compiled natively they
were still 1.1–3.4× slower warm (WebAssembly builds lost too), because V8's strings (ropes, slices, one-byte
strings) beat a UTF-8 runtime at slicing and concatenating, and the one realistic end-to-end path
(HTML tokens handed to the JS tree builder) was 2.4× slower even cold. The only win was a cold
parse of a large stylesheet, about 3 ms once per file, not worth shipping per-platform binaries.
So nothing native ships, and the experiment was removed; its measurements are in git history
(`packages/native/RESULTS.md`, deleted along with scriptc).

## The node layer (`packages/dom/src/nodes`)

### NodeImpl: one hidden class for every node

Every public node wrapper (`HTMLDivElement`, `Text`, `Document`, ...) owns exactly one
`NodeImpl` in `node[$impl]`. `NodeImpl` (nodes/NodeImpl.ts) is a single class whose constructor
initializes every field, so all nodes share one V8 hidden class. Wrappers have many
prototypes and therefore many hidden classes; walking fields on wrappers goes megamorphic
(measured ~3x slower on a 30-class tree). All hot internal algorithms walk `NodeImpl`.

| field | meaning |
| --- | --- |
| `node` | public wrapper |
| `type` | nodeType |
| `doc` | node document (`Document` wrapper; a Document points to itself) |
| `parent first last prev next` | tree links (doubly linked children list) |
| `childCount` | number of children |
| `flags` | `F_*` bits (constants.ts): connected, HTML-ness, which wrapper hooks exist, ... |
| `tag` | integer id of a known HTML local name (`tags.ts`), 0 otherwise |
| `name` | element local name / doctype name / PI target / attr local name |
| `ns`, `prefix` | element namespace and prefix |
| `attrs` | `AttrRecord[]` in attribute-list order, or null |
| `data` | CharacterData data / Attr value |
| `id` | mirrored id attribute ("" if none); feeds the id index and `#id` matching |
| `classes` | cached class tokens (null = recompute) |
| `cache` | `NodeCache` or null: per-node caches for aria/css (nodes/cache.ts) |

Rules: never add fields outside the constructor; never change a field's value kind; put
non-hot, type-specific state on the wrapper (e.g. input value lives on `HTMLInputElement`).
New hot fields need an entry in this table.

### Wrappers

Wrapper internal fields are keyed by registered symbols from `src/keys.ts` (`this[$impl]`,
`this[$listeners]`, `doc[$version]`, ...; re-exported by `@ctrl/dom/internal`), never by
`_`-prefixed strings: `Object.keys(node)`, `for...in` and `JSON.stringify` must see no internals
(Jest's diff/--json walk own enumerable keys). Methods may keep `_name` (prototype members are
not enumerable). New wrapper fields get a key in keys.ts.

Memory rules for per-node state (every rendered element pays them):
- Rarely used per-wrapper objects (`childNodes`, `children`, `shadowRoot`, `style`, `classList`,
  `dataset`, `attributes`, the listener map) are `declare`d fields added on first use, never
  initialized in constructors: an initialized-to-null field costs every node a slot. Reads treat
  "absent" like null (`== null`, `??=`).
- Attribute lists are exact-size arrays created with `new Array(n)` (one elements kind, no
  `push` slack) and `AttrRecord` holds only `localName`, `value` and a `rare` slot for
  namespace/prefix/`Attr` node; hot loops read `rare === null` directly.
- Small lists in general (attributes, per-type listener lists, a fragment's children during
  insertion) are built at their exact size: the first `push` onto `[]` allocates a 17-slot
  backing store, which dominated React root containers (~80 one- or two-listener lists each).
  Measure allocation with `pnpm bench` (`allocMB`/`gcMs` extras) when touching hot paths.

`EventTarget → Node → Element → HTMLElement → HTML*Element`, `CharacterData → Text/Comment`,
`Document`, `DocumentFragment → ShadowRoot`, `DocumentType`, `Attr`. Wrapper fields are
initialized in constructors in a fixed order. Interface mixins (ParentNode, ChildNode, ...)
are implemented once in `nodes/mixins.ts` and installed on prototypes.

Interface objects are module-level singletons shared by all windows (no per-window class
copies; that is most of jsdom's/happy-dom's startup). Constructors that need the "current
global" (`new Text()`, `new Event()`, `new Image()`) use `window/current.ts`.

Because the modules outlive every window, module state must never keep a node, document or
window: in a reused test worker that keeps a finished file's realm (its global, window,
document and module graph) alive. Caches are weak or stamped on the document, pointers that
only matter during one operation (the cascade's ancestor-filter element, the matcher's scope)
are cleared when it ends, and memos hold their keys weakly. One trap is V8's own:
`Object.create(proto)` caches the map it builds on `proto`, owned by the calling realm, so for
prototypes every test file uses (interface prototypes, and the outer realm's
`Object.prototype`, which Jest's `module.exports` objects inherit from and bundlers' `__toESM`
passes to `Object.create`) the first file to call it would stay alive for the whole worker.
`window/isolation.ts` has a permanent realm build those maps first. The leak suite
(`tests/compat/test/leaks`) pins all of this.

### Mutation algorithms (`nodes/tree.ts`, `nodes/attributes.ts`, `nodes/CharacterData.ts`)

All tree, attribute and character-data mutations go through these functions. They own the
bookkeeping:

- `F_CONNECTED` on every node of a subtree inserted into / removed from a connected parent;
- the document id index (`Document._ids`, `_idAdd/_idRemove/_idLookup`);
- focus fixup (`Document._focused` cleared when the focused element is disconnected);
- mutation records via `observers/queue.ts`, only when `activeObservers > 0`;
- element hooks, called only when the corresponding flag is set on the element:
  `F_CONNECT_HOOK` → `_connectedSteps/_disconnectedSteps`, `F_ATTR_HOOK` →
  `_attributeChangedSteps`, `F_CHILDREN_HOOK` → `_childrenChangedSteps`; `_cloningSteps`
  always runs on clone;
- `Document._version++` on every mutation. Caches anywhere (live collections, selector
  results, roles, names, computed style) are stamped with the version they were computed at.
  `Document._styleVersion++` when style sheets change.

Parser / clone fast paths build detached trees with `appendDetached` and
`appendAttributeDetached` (no records, hooks or version bumps). The parser must call
`_childrenChangedSteps()` itself on elements with `F_CHILDREN_HOOK` after finishing their
children (e.g. `<option>`, `<textarea>`, `<style>`), and connected hooks run when the
finished fragment is inserted.

### Iteration helpers (`nodes/traverse.ts`)

Allocation-free preorder iteration: `for (let n = root.first; n !== null; n = nextInTree(n, root))`.

| testing-library | `packages/testing-library` | the `@testing-library/dom` API |

## Performance invariants (enforced in review and by bench/)

1. No per-call allocation in hot read paths (attribute reads, traversal, matching).
2. Lazy everything: `childNodes`, `classList`, `dataset`, `style`, `attributes`, Attr nodes,
   computed styles, live collections are created on first use.
3. Zero cost when unused: mutation observers, ranges, custom elements, stylesheets.
4. Caches are version-stamped, never eagerly invalidated by walking.
5. Startup: importing `@ctrl/dom` and creating a window must stay far below happy-dom
   (target: < 15 ms import from the bundled build, < 1 ms `createWindow`). Where a fresh Vitest
   worker's time goes, why `installGlobals` loads Node's undici, and why a V8 startup snapshot
   of the DOM was measured and not shipped: bench/README.md, "Worker startup".
6. No `Proxy` on hot paths (indexed access on collections is the main temptation).

## Memory: what may stay reachable (enforced by `tests/compat/test/leaks`)

After `window.close()` (environments call it on teardown) a window, its documents, nodes,
observers, ranges, iframes' nested windows and custom element definitions are collectable, and
`installGlobals()`'s uninstall restores every host global. Within a live document, removing a
subtree releases it: version-stamped caches that could still reference removed nodes (selector
results per root, aria's label index, live collection / computed NodeList snapshots, a form's
listed controls) are kept in `Document[$derived]` or registered with `holdSnapshot`
(nodes/derived.ts) and dropped by `remove()`. Snapshots rooted in a detached node are never
registered, so a detached tree (a clone, an unmounted container) is not kept alive by the
document. Intentionally retained:

- the current window (`window/current.ts`) until it is closed or another window is created;
- a window's own state while it is open (its custom element registry, storage, history);
- host timers created through `window.setTimeout` & co. (they are the host's), until they fire,
  are cleared or the window closes (`close()` clears the ones created through the window's, or
  under @ctrl/dom-jest-environment / Vitest VM pools the file global's, setTimeout/setInterval);
- process-wide, bounded string caches (compiled selectors ≤ 2048, inline style blocks ≤ 2000,
  media query lists ≤ 500, `pattern` regexps ≤ 256, uppercase tag names ≤ 1024) and per-process
  interface objects;
- the host originals `installGlobals` captured (Node's own classes, not ours).
