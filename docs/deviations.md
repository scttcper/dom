# Intentional deviations from the specs

Each entry: what differs, why, and what a test would observe. Add entries when you choose
not to implement something a spec requires.

| Area | Deviation | Reason |
| --- | --- | --- |
| Window | Interface objects (`HTMLElement`, `Event`, ...) are shared module-level classes, not per-window copies. Constructors needing the current global use the most recently created/activated window (`window/current.ts`). | Per-window class creation dominates jsdom/happy-dom startup; tests use one window per file. |
| Scripting | `<script>` elements never execute; inline event handler attributes (`onclick="..."`) are not compiled. | Not needed to test React components; avoids `node:vm`. |
| Layout | No layout engine. Geometry (`getBoundingClientRect`, `offsetWidth`, ...) returns zeros unless mocked. | Same as jsdom/happy-dom; tests needing layout belong in a browser. |
| Nodes | `_impl`, `_listeners` and other internal fields are enumerable own properties of wrappers. | Plain fields are the fastest representation in V8; DOM nodes are not meant to be enumerated. |
| Window | Installed as a test environment, the host global *is* the window (`window === globalThis`), with window members forwarded to a `Window` instance; events dispatched at the window have that instance as `target`/`currentTarget`, not `globalThis`. `document.defaultView` returns the host global while installed. | Same model as Vitest's jsdom/happy-dom environments; avoids a vm context per test file. |
| Window | Navigation never loads a document: `location.href = ...`, `assign`, `replace` and the component setters only update the URL and session history (fragment-only changes fire `hashchange`); `reload()` does nothing. | No navigation/network (CLAUDE.md priority 3); keeps SPA routers working. |
| Window | `window.close()` closes the window for good (cancels pending animation frames, idle callbacks and window tasks) instead of being ignored for non-script-opened windows. | Matches jsdom/happy-dom; environments use it on teardown. |
| Window | `resizeTo`/`resizeBy` change `innerWidth`/`innerHeight`, re-evaluate media queries and fire `resize`; assigning `innerWidth`/`innerHeight`/`devicePixelRatio` also re-evaluates media queries (synchronously). Browsers ignore `resizeTo` on normal windows. | Lets tests drive responsive components without mocking `matchMedia`. |
| Window | `requestAnimationFrame` runs frames on a 16 ms host `setTimeout` (looked up at call time so fake timers control it); `requestIdleCallback` runs after 1 ms with a 50 ms deadline. | No rendering loop; host timers make them deterministic under fake timers. |
| Window | `scroll`/`scrollTo`/`scrollBy` only record `scrollX`/`scrollY` (clamped at 0, never at a maximum) and fire no `scroll` events. | No layout. |
| Window | `matchMedia` (until the css area registers an evaluator) uses fixed "desktop browser" values for discrete features (light scheme, no reduced motion, fine pointer, hover); override per window with `createWindow({ mediaFeatures })`. | No real display; deterministic tests. |
| Window | Each window has its own localStorage unless created with `shareStorageWith` (then `storage` events flow between them). | Test isolation; browsers share per origin. |
| Window | `ResizeObserver`/`IntersectionObserver` never invoke their callbacks. | No layout; libraries only need them constructible. |
| Window | `navigator.userAgent` is `Mozilla/5.0 (<os>) AppleWebKit/537.36 (KHTML, like Gecko) rtd/0.0.0` (configurable); `navigator.clipboard` is an in-memory clipboard per window. | No real browser/system clipboard. |
| Aria | Accessible names do not insert spaces between inline children that old jsdom reported as `display: block` (e.g. "aria 1.11.2", not "aria 1.1 1.2"). | Matches dom-accessibility-api on jsdom 30 / the CSS display of the elements; four upstream assertions recorded on old jsdom are annotated in packages/aria tests. |
| Aria | Without a `getComputedStyle` option, name computation never calls `window.getComputedStyle` and never logs jsdom's pseudo-element "Not implemented" errors. | Pseudo-element content comes from the css fast path; no noisy console errors. |
| Aria | `aria-labelledby` on an element not attached to a document yields no references instead of throwing a TypeError. | Upstream's throw is an implementation accident (null root), not specified behavior. |
| Events | `DragEvent.dataTransfer`, `ClipboardEvent.clipboardData`, `InputEvent.dataTransfer` and `relatedTarget` init members accept any object (no WebIDL interface check). | Testing Library's `fireEvent` passes plain objects (`{ dataTransfer: { files } }`) to event constructors; browsers would throw, jsdom never sees these constructors. |
| Events | `DataTransfer` is always in read/write mode (no protected/read-only drag data store modes); `DataTransferItem.getAsString` calls back in a microtask instead of a task. | No real drag-and-drop operation exists; a microtask also completes under fake timers (user-event awaits it). |
| Events | `Touch.target` is the init target; touch target lists are retargeted on the event path but Touch objects are not re-created per path entry. | Shadow DOM + touch retargeting is not observable in React component tests. |
| Events | `UIEvent.which`, `KeyboardEvent.keyCode/charCode` return their init dictionary values (default 0) instead of being derived from `button`/`key`. | Same as jsdom (drop-in compatibility). |
| Events | `window.event` is one module-level value shared by all windows. | One current window (see Window row). |
| Events | When dispatch step 6 is skipped (target equals the retargeted relatedTarget), target/relatedTarget are left untouched, as the spec text and jsdom do; WPT `relatedTarget.window.js` expects them reset/retargeted. | Follow the normative algorithm; not observable without shadow DOM. |
| Events | Listener exceptions dispatch an `ErrorEvent` at the window; if not canceled they go to `setUncaughtExceptionHandler` (default: `console.error(error.stack)`, like jsdom's virtual console). | Matches jsdom; the Vitest jsdom environment's window "error" listener (re-emit as `uncaughtException`) works unchanged. See src/events/report.ts. |
| CSS | `getComputedStyle` keeps author-specified color serialization (`red`, `#f00`) instead of converting to `rgb()`. | Matches happy-dom and jsdom ≤26; existing suites assert `toHaveStyle({ color: 'red' })`, which jest-dom compares against computed values (jsdom 30's rgb() conversion broke them). @rtd/jest-dom additionally compares colors canonically. |
| HTML | Custom element reactions run at the end of each core `insert`/`remove`/attribute change (nodes/create.ts `ceReactionsPending`), not at the end of each `[CEReactions]` method. For compound operations (`replaceChildren`, moving a connected node) callbacks of an earlier sub-step can run before a later one starts, e.g. `disconnectedCallback` runs before the moved node is re-inserted. | Avoids wrapping every DOM method; the tree is always consistent when callbacks run, and the common orders (constructed → attributeChanged → connected) match browsers. |
| HTML | Customized built-in elements are supported for `new`, `createElement(…, { is })` and `customElements.define`, but the parser ignores `is="…"` attributes. | Rarely used; Safari does not ship them. |
| HTML | Focus: `document.hasFocus()` is true iff an element is focused (no system focus model, as in jsdom). `:focus-visible` matches the focused element unless the focus came from a pointer (user-event reports that via `notePointerFocus()`), except for text inputs/editing hosts. | No OS window focus; heuristic from Selectors 4. |
| HTML | Focusability uses the css area's computed `display:none` (author styles included) but not `visibility`, `content-visibility` or zero size. | No layout. |
| HTML | `innerText` approximates the rendered text collection steps without layout: block-ness comes from the UA default display of the tag (author `display` other than `none` is ignored), whitespace collapses as `white-space: normal` except in pre/listing/xmp/plaintext/textarea, `visibility` and `text-transform` are ignored, replaced elements contribute nothing and `<select>` lists its options one per line. jsdom has no `innerText`. | No layout engine; covers what component tests read. |
| HTML | Links never navigate: activating `<a href>`/`<area href>` only sets `location.hash` for same-document fragment links without `target`/`download`. | No navigation (CLAUDE.md priority 3). |
| HTML | Popovers and dialogs have no light dismiss / close watchers: clicking outside or pressing Escape does not hide popovers or cancel dialogs; `dialog.requestClose()` always fires a cancelable `cancel`. Toggle/close events are queued with `setTimeout(0)`. | No user-agent input handling outside user-event; macrotask timing matches "queue an element task". |
| HTML | Media elements never load: `networkState`/`readyState` stay 0 and `duration` is NaN, but `play()` resolves and toggles `paused` (firing `play`/`playing` in a task) and `pause()` fires `pause`. jsdom throws "not implemented" for these. | Components that call `play()` should not need mocks. |
| HTML | `<img>` never fetches: an image with `src`/`srcset` stays pending forever (`complete` false, as jsdom without resource loading; true only without a source), natural size 0, `decode()` resolves, no load/error events. A connected `<iframe>` (in a document with a window) gets a minimal nested browsing context: a Window (`parent`/`top` = outer window, `frameElement` = the iframe, never the current window) with an about:blank document or its parsed `srcdoc`; `src` is never fetched (about:blank content, document URL set to `src`), changing `src`/`srcdoc` later does not navigate, `load` fires asynchronously after insertion, removal closes it. `<frame>`/`<object>`/`<embed>` have no nested browsing context. `<canvas>.getContext()` returns null and `toDataURL()` returns `"data:,"`. `<link rel=stylesheet>` never fetches. | No network, no rendering. |
| HTML | `HTMLScriptElement.async` starts true for every script ("force async" cannot be told apart for parser-inserted scripts). | Scripts never run, so nothing depends on it. |
| user-event | `delay: 0` (the default): between actions and at the end of each API call, @rtd/user-event yields with `setImmediate` instead of upstream's `setTimeout(resolve, 0)` (≥1 ms in Node) **only if no timer could run during upstream's wait**: (1) default `advanceTimers`, `setImmediate` not faked/spied; (2) `globalThis.setTimeout/setInterval/clearTimeout/clearInterval` are still the observing wrappers user-event installs on import (re-installed at each API call; fake timers or a replaced global turn the shortcut off); (3) **no pending timer created through them is due within 4 ms** (deadlines tracked from creation, interval re-arm, clear and fire — so pre-existing 0 ms timers, clear-then-schedule, rAF shims built on `setTimeout(0)` all force the upstream wait; timers due later, e.g. a 16 ms animation frame or a 500 ms debounce, would not have run in upstream's wait either); (4) the number of live `Timeout` resources not created through the wrappers (`process.getActiveResourcesInfo()` minus tracked) has not grown since the last full wait (catches timers created through references captured before import; any short one existing at that time was flushed by that wait). Otherwise upstream's `setTimeout` + `advanceTimers` wait runs unchanged. Observable: microtasks, React scheduler tasks and effects flush between actions as before; every timer upstream's wait would run still runs before the next action and before the call resolves. Remaining gap: a timer created through a captured pre-import reference in the same action in which another untracked timer fires or is cleared. | Upstream's 1 ms per keystroke/pointer action dominates user-event's cost (`type(input, 'hello world')`: ~21 ms → ~0.4 ms on @rtd/dom). Pinned by packages/user-event/test/react (pre-existing 0 ms timer, clear-then-schedule, setTimeout(0) at call end), downstream/base-ui/repros/user-event-yield-heuristic-skips-timeout.test.ts and 10 consecutive Base UI rtd-full runs of SelectRoot/createItems. |
| user-event | `<input type="number">` on @rtd/dom: while typing intermediate strings that are not valid floating-point numbers (`"-1."`, `"1e"`), `value` is `""` (browser value sanitization) instead of upstream-on-jsdom's `String(Number(v))` (`"-1"`, `"-1500"` for `"-1.5e3"`). The UI value user-event edits, cursor positions and event counts are identical. | Upstream's normalization is a jsdom workaround; @rtd/dom keeps the UI value natively and sanitizes per https://html.spec.whatwg.org/#number-state-(type=number). |
| CSS | Detached (not connected) elements get computed values from the cascade instead of empty strings. | Tests often inspect elements before mounting; matches jsdom's practical behavior. |
| CSS | Logical shorthands such as `margin-inline` / `padding-block` are stored unexpanded in declarations. | No writing-mode/layout to resolve them against. |
| CSS | Assigning a property on a computed (read-only) declaration is silently ignored; `setProperty` still throws `NoModificationAllowedError`. | Avoids crashes in libraries that write to the result of getComputedStyle in sloppy mode. |
| CSSOM View | Assigned `scrollTop`/`scrollLeft` (and `scroll()`/`scrollTo()`/`scrollBy()` on elements, including `document.scrollingElement`) are stored and read back, clamped at 0 with no maximum; assignment fires no `scroll` event. `checkVisibility()` uses computed styles (display/content-visibility/opacity/visibility) but no box geometry. | No layout. jsdom parity: `fireEvent.scroll(el, { target: { scrollTop: 100 } })` and scroll-area components read the assigned value back. |
| CSS | `@container` and `@scope` rules are parsed and exposed in CSSOM but not applied in the cascade. | No layout (container size) and scoping proximity is rarely relied on in component tests. |
| Window | FormData is Node's undici class subclassed with the form constructor steps; it is resolved lazily (first construction) so importing @rtd/dom or creating a window does not load undici/zlib. `installGlobals` reads the host FormData once to restore it later. | Instances stay valid fetch/Request bodies (undici does not duck-type FormData); startup stays lean. |
| Window | No named access on the window (`window.myId` / `window["my-name"]` for elements with ids/names, https://html.spec.whatwg.org/#named-access-on-the-window-object). | It needs either a Proxy in front of the global (every global read in every test pays) or per-id getters maintained on each id mutation (a cost in the attribute/insert hot path); legacy code relying on it should use `document.getElementById`. |
| Events | `TouchEvent` init members `touches`/`targetTouches`/`changedTouches` accept touch-like plain objects and expose them unchanged through `TouchList` (only primitives throw). | jsdom has no `Touch` interface and keeps whatever was passed; `fireEvent.touchStart(el, { touches: [{ clientX }] })` is a common idiom (Base UI tests). |
| Window | `window.visualViewport` is absent unless the window is created with `visualViewport: true`. | jsdom parity: without layout a VisualViewport's numbers mislead positioning libraries (Floating UI falls back to the document element when it is missing). |
| Document | `document.open()`/`write()`/`writeln()`/`close()`: there is no script-inserted parser, so `write()` re-parses everything written since `open()` and replaces the document's children synchronously; `open(url, name, features)` delegates to `window.open`. | Scripts never run; this covers filling iframe documents in tests. |
| Animations | `Element.getAnimations()` / `Document.getAnimations()` return `[]`; `Element.animate()` is not provided. | No animation engine; code that probes `typeof el.animate` keeps its non-animated path, as on jsdom. |
| HTML | The `inert` attribute and `HTMLElement.inert` are implemented (jsdom does not support them), so libraries that feature-detect `inert` (e.g. Radix's `hideOthers`) use it instead of their `aria-hidden` fallback; tests asserting jsdom's fallback DOM differ. | Spec behavior; matches browsers. |
| WebIDL | Attributes/operations of ValidityState and the geometry interfaces (DOMRect, DOMPoint, DOMMatrix and their read-only/list variants) are enumerable with hidden internals, so `for...in` matches browsers. Nodes still keep enumerable `_impl`/`_listeners`/... own fields (and class-syntax non-enumerable members) for construction speed. | Per-instance property hiding costs too much on hot node paths; DOM nodes are printed by pretty-format's DOM plugin, not by enumerating keys. |
| Events | Event objects match the WebIDL/jsdom shape (only `isTrusted` is an own enumerable property; attributes/operations are enumerable prototype members; internals live in private fields), except that interfaces expose current-spec members jsdom lacks (`InputEvent.dataTransfer/getTargetRanges`, `PopStateEvent.hasUAVisualTransition`, `TouchEvent.getModifierState`), so `for...in` lists those too. | Spec additions; pretty-format output is identical to jsdom. |
| Forms | `validationMessage` for built-in constraint failures is jsdom's generic `"Constraints not satisfied"` by default; `createWindow({ validationMessages: "browser" })` switches to Chromium-like per-constraint text ("Please fill out this field.", ...). Custom validity messages are always returned as set and take precedence whenever `customError` is set. | The text is UA-defined (https://html.spec.whatwg.org/#dom-cva-validationmessage); suites written against jsdom (e.g. react-aria) assert jsdom's string, so drop-in compatibility wins. |
| Forms | No form submission navigation: a submission that is not canceled ends after the `submit` event; `form.submit()` does nothing observable. | No navigation in this environment. |
| Forms | Form-associated custom element callbacks (`formAssociatedCallback`, `formResetCallback`, `formDisabledCallback`) run synchronously instead of as queued custom element reactions; owner/disabled changes are detected only when the element itself is connected, disconnected, or has `form`/`disabled` changed. `formStateRestoreCallback` never runs. | Form owners are computed on demand rather than tracked through every ancestor/fieldset mutation. |
| Forms | A `<select size=0>` has display size 0 (no default selection), per the spec's parsing rule; browsers treat 0 like 1. | Spec text; matches jsdom. |
