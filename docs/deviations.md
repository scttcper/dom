# Intentional deviations from the specs

Each entry: what differs, why, and what a test would observe. Add entries when you choose
not to implement something a spec requires.

## Compat profiles

Test suites written for jsdom feature-detect: a library that finds `PointerEvent`, `matchMedia`
or `ResizeObserver` takes its browser path, and a suite that polyfills a missing API keeps ours
instead of its mock. So what a test can see depends on the window's `compat` profile:

- `jsdom-26`: what jest-environment-jsdom 30 exposes (it ships jsdom 26.1). The default of
  jest-environment-ctrl-dom.
- `jsdom-30`: what jsdom 30 exposes (Vitest's jsdom environment). The default of
  vitest-environment-ctrl-dom, the Vitest plugin and `createWindow()`.
- `modern`: everything @ctrl/dom implements.

Set it with `testEnvironmentOptions: { compat }` (Jest), `environmentOptions: { "ctrl-dom": {
compat } }` or `ctrlDom({ compat })` (Vitest), or `createWindow({ compat })`. The table lists every
API @ctrl/dom has that jsdom 26 or jsdom 30 lacks, and the profiles that expose it; the full lists
are `COMPAT` in packages/dom/src/window/compat.ts, and tests/compat/test/surface/ checks each jsdom
profile against the real jsdom, so a new API cannot ship without a row here. A profile applies
where the window is installed as the global (the environments, `installGlobals`): a window used
directly, or an iframe's `contentWindow`, has every interface object, since they are shared.

### jsdom's "Not implemented" errors

The jsdom profiles also report what jsdom reports as not implemented, with jsdom's exact
`Error` (message and `type`) at the same points, forwarded to the test's `console.error` the way
that profile's jsdom environment does (Jest with jsdom 26: once, the Error; Jest with jsdom 27+:
its stack, then the Error; Vitest: `console.error(stack, undefined)`):

| Reported when | `jsdom-26` message | `jsdom-30` message |
| --- | --- | --- |
| A navigation goes beyond a fragment change: `location.href`/`assign()`/`replace()`/the URL component setters, `location.reload()`, an activated link whose target is empty, `_self`, `_parent` or `_top` (in a task; `download` is ignored, as in jsdom) | `navigation (except hash changes)` | `navigation to another Document` |
| `form.submit()`; a submission whose `submit` event was not canceled (`requestSubmit()`, a submit button, implicit submission) | `HTMLFormElement.prototype.submit` / `.requestSubmit` | `HTMLFormElement's submit() method` / `requestSubmit() method` |
| `window.alert`, `confirm`, `prompt`, `print`, `open`, `focus`, `blur`, `moveTo`, `moveBy`, `resizeTo`, `resizeBy`, `scroll`, `scrollTo`, `scrollBy` | `window.alert` | `Window's alert() method` |
| `HTMLMediaElement` `play`, `pause`, `load`, `addTextTrack` | `HTMLMediaElement.prototype.play` | `HTMLMediaElement's play() method` |
| `getComputedStyle(el, pseudo)` with a non-empty pseudo-element | `window.getComputedStyle(elt, pseudoElt)` | `Window's getComputedStyle() method: with pseudo-elements` |

What @ctrl/dom does at these points is unchanged (it implements media playback, scrolling,
resizing and pseudo-element styles; it never navigates). `modern` reports nothing, and neither
does a window without an environment (`createWindow()`: install a receiver with
`setNotImplementedHandler` from `@ctrl/dom/internal`). Differences from jsdom: `requestSubmit()` on
a disconnected form neither fires `submit` nor reports (spec: it cannot navigate; jsdom does both),
and a `method="dialog"` submission closes its dialog instead of reporting. tests/compat/test/not-implemented/
compares every case with the real jsdom 26 and 30. Suites assert on these (Sentry: "JSDOM throws an
error on navigation"), so a drop-in reports them.

## In every profile

| Area | Deviation | Reason |
| --- | --- | --- |
| Window | Interface objects (`HTMLElement`, `Event`, ...) are shared module-level classes, not per-window copies. Constructors needing the current global use the most recently created/activated window (`window/current.ts`). | Per-window class creation dominates jsdom/happy-dom startup; tests use one window per file. |
| Scripting | `<script>` elements never execute; inline event handler attributes (`onclick="..."`) are not compiled. | Not needed to test React components; avoids `node:vm`. |
| Layout | No layout engine. Geometry (`getBoundingClientRect`, `offsetWidth`, ...) returns zeros unless mocked. | Same as jsdom/happy-dom; tests needing layout belong in a browser. |
| Nodes | Internal state of wrappers (nodes, documents, windows, collections, CSSOM objects) lives in enumerable own **symbol-keyed** fields (`Symbol.for("rtd.impl")`, ... from `src/keys.ts`): `Object.keys`, `for...in` and `JSON.stringify` see nothing (as on jsdom), but `Object.getOwnPropertySymbols`/object spread do. | Per-instance non-enumerable definitions cost ~80 ns per field per node; symbol keys keep plain constructor-initialized fields. Cost: megamorphic symbol loads are ~2 ns slower than named ones (pure DOM microbenches such as `insertBefore`/`childNodes[i]` loops up to ~30% slower; React workloads and the 100-file suite within noise). |
| Collections | `HTMLCollection` (except `form.elements` / `document.forms`), `NamedNodeMap` and live `NodeList`s other than `childNodes` have no WebIDL named properties (`coll.someId`, `el.attributes.class`) and no own index properties: `coll[0]` is an accessor on the prototype, so `Object.getOwnPropertyNames(coll)` is empty, `delete coll[0]` succeeds silently, expandos named like an index or a member name are accepted, and `i in coll` is true for every installed index (https://webidl.spec.whatwg.org/#legacy-platform-object-getownproperty). Brand checks on `length` are skipped (`Object.create(coll).length` works). | Named/indexed properties need a `Proxy`, which costs every property read (~100 ns vs ~45 ns for a prototype getter, ~5 ns own data property); `namedItem()`/`getNamedItem()`/`item()` and iteration work. jsdom uses Proxies. WPT dom/collections and the `attributes*` tests record the difference. |
| Collections | `NodeList.prototype.values` / `[Symbol.iterator]` and `HTMLCollection.prototype[Symbol.iterator]` are @ctrl/dom's own iterator, not `%Array.prototype.values%` as WebIDL specifies (https://webidl.spec.whatwg.org/#es-iterable). Same `%ArrayIteratorPrototype%.next` semantics: index and length read on each step (live lists show changes), done stays done, `[object Array Iterator]`, iterator helpers, works on any array-like via `.call`. `forEach`, `keys` and `entries` are still Array.prototype's. | V8 runs Array.prototype.values generically on non-array objects, ~30 ns per element, and Testing Library `Array.from()`s every query result: stock `getByText` on a 4,500-element page is 18% faster. WPT "Iterator behavior of Node.childNodes" checks the identity (an expected failure already). |
| Nodes | `moveBefore()` (https://dom.spec.whatwg.org/#move) also runs the children changed steps of the old and new parent, and the html moving steps are limited to the `_movingSteps` hook (no focus fixup; custom element `connectedMoveCallback` is enqueued only for light-tree descendants, not shadow-including ones). | Our `<option>`/`<select>`/`<style>`/`<title>` state is maintained by children changed steps; skipping them would leave stale state after a move. |
| Window | Installed as a test environment, the host global *is* the window (`window === globalThis`), with window members forwarded to a `Window` instance. Events at the window still expose the host global (`event.target`, `currentTarget`, the listener's `this`, `composedPath()`), and `document.defaultView` returns the host global while installed. | Same model as Vitest's jsdom/happy-dom environments; avoids a vm context per test file. |
| Window | Navigation never loads a document: `location.href = ...`, `assign`, `replace` and the component setters only update the URL and session history (fragment-only changes fire `hashchange`); `reload()` does nothing. | No navigation/network (CLAUDE.md priority 3); keeps SPA routers working. |
| Window | `window.close()` closes the window for good (cancels pending animation frames, idle callbacks and window tasks) instead of being ignored for non-script-opened windows. | Matches jsdom/happy-dom; environments use it on teardown. |
| Window | `resizeTo`/`resizeBy` change `innerWidth`/`innerHeight`, re-evaluate media queries and fire `resize`; assigning `innerWidth`/`innerHeight`/`devicePixelRatio` also re-evaluates media queries (synchronously). Browsers ignore `resizeTo` on normal windows. | Lets tests drive responsive components without mocking `matchMedia`. |
| Window | `requestAnimationFrame` runs frames on a 16 ms host `setTimeout` (looked up at call time so fake timers control it); `requestIdleCallback` runs after 1 ms with a 50 ms deadline. | No rendering loop; host timers make them deterministic under fake timers. |
| Window | `scroll`/`scrollTo`/`scrollBy` only record `scrollX`/`scrollY` (clamped at 0, never at a maximum) and fire no `scroll` events. | No layout. |
| Window | In jest-environment-ctrl-dom and Vitest VM pools, `Object.defineProperty`, `Object.defineProperties` and `Reflect.defineProperty` of the test file's realm always define **configurable** properties on interface objects and their prototypes (other targets keep the usual defaults). | Interface objects are shared by the files of a worker and undone at teardown (`restoreInterfaces`); a non-configurable patch cannot be undone. shadow-dom-testing-library adds `ShadowRoot.prototype.outerHTML` that way, and the next file in the worker crashed calling the leftover getter on the prototype (React Aria `ariaHideOutside` + `DOMFunctions`). |
| Window | `matchMedia` (until the css area registers an evaluator) uses fixed "desktop browser" values for discrete features (light scheme, no reduced motion, fine pointer, hover); override per window with `createWindow({ mediaFeatures })`. | No real display; deterministic tests. |
| Window | Each window has its own localStorage unless created with `shareStorageWith` (then `storage` events flow between them); an iframe's nested window shares its parent's, and same-origin frames of one top-level window share sessionStorage, as in browsers. | Test isolation; browsers share per origin. |
| Window | Assigning a function to a Storage member name (`localStorage.getItem = vi.fn()`), or defining a function/accessor property on a Storage object, creates a real own property instead of calling the named setter (`setItem("getItem", ...)`). | Lets tests mock Storage methods directly, like on happy-dom; every other assignment follows WebIDL [[Set]]/[[DefineOwnProperty]]. |
| Window | `setTimeout`/`setInterval`/`clearTimeout`/`clearInterval` are the host's (Node's or the installed fake clock's): handles are Node `Timeout` objects rather than positive integers, string callbacks are not compiled, timer nesting clamping does not apply, and an exception thrown by a callback reaches the host as an uncaught exception instead of a window `error` event. They are still owned by the window, like jsdom's: `window.setTimeout`/`setInterval` (Window methods that call the host's current functions) and, in jest-environment-ctrl-dom and vitest-environment-ctrl-dom's VM pools, the test file's global `setTimeout`/`setInterval` (thin wrappers, `trackGlobalTimers`) record each handle on the window; `window.close()` (environment teardown) clears the pending ones, and a closed window's setTimeout/setInterval return 0 without scheduling (jsdom's `timerInitializationSteps`). Fake timers installed on the global replace the wrappers and restore them; timers created on a fake clock are not tracked through the global. Vitest's per-worker `setup()` does not wrap (it tears down once per worker). | Fake timers (Vitest/Jest/sinon) must keep controlling `window.setTimeout`; no script execution; an uncaught error failing the test is more useful than a logged `error` event. Window ownership: long timers left by app code (TanStack Query GC, polling) otherwise kept each finished Jest file's vm context and module graph alive (Sentry: 7.2 MiB retained per file vs 0.18 on jsdom). Cost: one `Map.set` per call (~50–80 ns over Node's setTimeout+clearTimeout); fired/cleared handles are swept lazily via Node's `Timeout#_destroyed`. |
| Window | Location's `toString`, `valueOf` and `@@toPrimitive` are non-configurable own properties, but its other members (href, the URL component accessors, assign/replace/reload, ancestorOrigins) are ordinary configurable `Location.prototype` members, not [LegacyUnforgeable] own properties; Location is not an exotic object (`Object.setPrototypeOf`/`Object.preventExtensions` on it behave ordinarily). | `vi.spyOn(location, "assign")` keeps working; avoids a Proxy around `location`. |
| Window | `IntersectionObserver` and `ResizeObserver` (in the profiles that expose them) never invoke their callbacks; `observe`/`unobserve`/`disconnect`/`takeRecords` keep their bookkeeping. | No layout, so nothing is ever observed to intersect or resize; component libraries construct them unconditionally. Tests that need entries mock them. |
| Window | No `screen.orientation` (ScreenOrientation), like jsdom and happy-dom. | With a fixed `angle` of 0 it hid rotation from code that reads `window.orientation`: React Aria's keyboard tracking (and its test polyfill, which installs a `screen.orientation` backed by `window.orientation` only when there is none). |
| Network | `XMLHttpRequest` sends requests through Node's `http`/`https` modules, like jsdom: no CORS checks or preflights, no `file:` URLs, and synchronous requests (`open(…, false)`) throw `NotSupportedError` from `send()`. Closing the window aborts requests in flight without events; `timeout` runs on the window's timers. Cookies go through the window's jar (same-origin, or cross-origin with `withCredentials`), which drops `HttpOnly` cookies. | A test process has no same-origin boundary to protect, and jsdom's synchronous XHR spawns a worker per request for an API component tests do not use. Building on `http` keeps MSW (which mocks the `http.ClientRequest` XHR creates) and nock working, and the modules load only on first use. |
| Network | Where jsdom 30's XHR departs from the spec, ours follows it: `getAllResponseHeaders()` combines repeated names and sorts them; `responseURL` is `""` after `abort()`; a timeout fires no extra `progress` event and leaves `readyState` DONE; a `URLSearchParams` body is sent as `application/x-www-form-urlencoded`; `responseXML.contentType` is the response's MIME type. | https://xhr.spec.whatwg.org/; tests/compat/test/xhr/xhr.test.ts pins each difference with its spec section. |
| Window | `AbortSignal` is the host's (Node's) class, except that `AbortSignal.timeout(ms)` schedules its abort on the window's timers (like jsdom's `globalObject.setTimeout`) and aborts with a `TimeoutError` DOMException "The operation timed out." (jsdom's message); `AbortSignal.prototype.constructor` is still Node's constructor. Without a current window it falls back to Node's. | Node's timeout runs on an internal real-time timer, which fake timers and the virtual clock never advance: React Aria's `runAfterKeyboard` waits on `AbortSignal.timeout(600)` under `jest.useFakeTimers()`. Signals, `AbortController`, `abort()`/`any()` and `instanceof` stay Node's so they work with Node APIs. |
| HTML | Interactive constraint validation (form submission, `reportValidity()`) fires `invalid` events but does not "report the problems": no validation UI and no focus moved to the first invalid control. | jsdom and happy-dom leave focus alone too; a focus move counts as a programmatic focus (React Aria's focus-visible tracking then shows focus rings its jsdom-written Form tests assert are absent). |
| HTML | The `hidden` IDL getter returns `true` for `hidden="until-found"` instead of `"until-found"`; the setter still writes `until-found` for that string (https://html.spec.whatwg.org/#dom-hidden). | jsdom (26, 30) and happy-dom return `true`, and React Aria's disclosure tests assert `panel.hidden === true` after its hooks set `hidden="until-found"`. WPT hidden-idl subtests are recorded as known failures. |
| HTML | Focusing an element in a nested document makes the container `<iframe>` the focused area of each ancestor document (`document.activeElement`, blur of what was focused there) without firing `focus`/`focusin` at the container (https://html.spec.whatwg.org/#focus-update-steps fires them at every new focus-chain entry). | jsdom (26 and current) fires none there either; React Aria's `useFocusVisible` treats that unannounced focus as virtual-modality focus, so its iframe tests written for jsdom failed. |
| Window | `navigator.userAgent` is `Mozilla/5.0 (linux) AppleWebKit/537.36 (KHTML, like Gecko) rtd/0.0.0` and `navigator.platform` is `""` on every host (both configurable: `createWindow({ userAgent, platform })`, environment options); jsdom reports `""` and `Mozilla/5.0 (${process.platform}) … jsdom/x`. `hardwareConcurrency` is the host's CPU count, like jsdom. `navigator.clipboard` is an in-memory clipboard per window. | Host-independent results: React Aria's `isMac()` (`/^Mac/i.test(navigator.platform)`) made Ctrl shortcuts behave as Meta on macOS only. The pinned UA is what jsdom produces on Linux CI. No real browser/system clipboard. |
| Window | `navigator.clipboard` is [Replaceable]-style: assigning it (strict mode included) defines an own data property on the navigator; deleting that brings the real clipboard back. The spec attribute is `readonly` (browsers throw in strict mode). | jsdom has no `navigator.clipboard`, so suites stub it with `Object.assign(navigator, { clipboard })` (29 Sentry spec files); user-event's `defineProperty` stub and `spyOn(navigator.clipboard, …)` work as before. |
| Window | Window operations (`requestAnimationFrame`, `setTimeout`, `matchMedia`, `scrollTo`, …) accept the host global the window is installed on as `this` (and `undefined`, meaning the current window), resolving it to the installed Window; any other receiver throws "Illegal invocation". | Under the environments the global is the host global, not a Window; rrweb binds an iframe's `requestAnimationFrame` to the page global (WebIDL lets an operation on a global accept the global). Cost on the normal path: one symbol load. |
| Window | No `fetch`, `Request` or `Response` on the window (`Headers`, `FormData` exist), like jsdom. jest-environment-ctrl-dom also removes Node's from the test global (`testEnvironmentOptions.nodeFetch: true` keeps them); vitest-environment-ctrl-dom keeps Node's, like Vitest's jsdom environment. Other Node web globals jsdom's window lacks stay in jest-environment-ctrl-dom (streams, `structuredClone`, `BroadcastChannel`/`MessageChannel`, `setImmediate`, `Performance*` entries, `URLPattern`, `CryptoKey`/`SubtleCrypto`): their presence does not switch libraries onto different code paths the way fetch does (React's scheduler already prefers `setImmediate` under Node). | jest-fetch-mock (and similar) use the environment's fetch primitives when all exist and a polyfill otherwise; with undici's `Request` relative routes stop matching. Removal is a `delete`, which does not materialize Node's lazy undici globals. |
| Window | jest-environment-ctrl-dom exposes `environment.dom` with only `window` and `reconfigure({ url })` (jsdom's `JSDOM` object under jest-environment-jsdom); `reconfigure` sets the document URL without navigation and rejects `windowTop`. | Custom environments and @sentry/jest-environment (`global.jsdom = this.dom`, used by `setWindowLocation()`) need the URL setter; the rest of the JSDOM API has no use without jsdom. |
| Aria | Accessible names do not insert spaces between inline children that old jsdom reported as `display: block` (e.g. "aria 1.11.2", not "aria 1.1 1.2"). | Matches dom-accessibility-api on jsdom 30 / the CSS display of the elements; four upstream assertions recorded on old jsdom are annotated in packages/aria tests. |
| Aria | Without a `getComputedStyle` option, name computation and the accessibility-tree checks (ByRole, `isInaccessible`, `getRoles`) never call `window.getComputedStyle` while it is @ctrl/dom's own, and never log jsdom's pseudo-element "Not implemented" errors. Once user code replaces or spies on it (`window.getComputedStyle = el => el.style`, `vi.spyOn(window, "getComputedStyle")`), styles are read through it where upstream would, so results match upstream but call counts can differ. | Pseudo-element content and visibility come from the css fast path (one identity check per query); no noisy console errors. |
| Aria | `aria-labelledby` on an element not attached to a document yields no references instead of throwing a TypeError. | Upstream's throw is an implementation accident (null root), not specified behavior. |
| Aria | Roles follow aria-query@5.3.0 / Testing Library, not current WAI-ARIA / HTML-AAM: the first `role` token is used as written (no fallback to the next valid token, no ASCII case folding, abstract/unknown roles not ignored, no presentational-role conflict resolution, unnamed explicit `form`/`region` kept), and implicit roles ignore context and newer mappings (`aside`/`section` context, `th` scope inference, `hgroup`, `s`, `search`, `input[switch]`). WPT wai-aria/html-aam failures in packages/dom/test/wpt/expectations/aria.json. | `*ByRole` on stock Testing Library behaves this way; changing it would make queries find different elements (drop-in compatibility). |
| Aria | Accessible names follow dom-accessibility-api@0.5.16, not current AccName / HTML-AAM: no flat-tree (shadow DOM / slot) traversal, no `placeholder`/`aria-placeholder` or `figcaption` name sources, button inputs named from `value` before `<label>`, U+00A0 trimmed and collapsed, no `::before`/`::after` content by default (Testing Library does not enable pseudo-element support).
