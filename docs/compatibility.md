# Compatibility

How `@ctrl/dom` is checked against what it replaces. Intentional differences from the specs and
from jsdom are listed, with the reason for each, in [deviations.md](deviations.md), and
[spec-coverage.md](spec-coverage.md) maps spec sections to the tests that cover them.

## Upstream test suites

Each package's own tests, ported from its repository, pass on `@ctrl/dom`:

- Testing Library DOM: 1,163 tests
- React Testing Library: 248
- jest-dom: 313
- user-event: 653 (+ 4 skipped)
- dom-accessibility-api, plus the WPT accname tests: 159/159

Stock jest-dom on `@ctrl/dom` (the environment swapped, nothing else) passes every test that
isn't skipped.

## Spec suites

- html5lib: tokenizer 7,050/7,050, tree construction 1,793/1,793
- web-platform-tests: selectors 1,319/1,319, about 54k dom subtests, about 47k reflection checks
- css-tokenizer-tests: 288/288

## Differential tests against jsdom

[tests/compat](../tests/compat/README.md) runs the same scenarios on jsdom and on `@ctrl/dom`
and compares what they observe: 701/701 form scenarios agree, with spec-pinned corrections where
jsdom is wrong, and the React form scenarios pass in all three modes.
