# ctrl-dom

`@ctrl/dom` is a faster replacement for jsdom and happy-dom when testing React components with
Vitest or Jest. It also comes with its own Testing Library (`@testing-library/react`, `/dom`,
`/user-event` and `/jest-dom`), built on the same DOM, which makes queries and user events
faster still.

It matches what it replaces: jsdom's globals, and Testing Library's exports, behavior, error
messages and `prettyDOM` output, so existing tests run unchanged. Swap only the DOM and keep
stock Testing Library, or swap the whole stack for the biggest speedup;
[Performance](#performance) has the numbers.

## Use it

Not published yet. `pnpm build` assembles the publishable packages under `release/`, and
`pnpm test:pack` installs their tarballs into a fresh project and runs every setup below.

Vitest (>= 5), whole stack: the environment plus your `@testing-library/*` imports routed to
`@ctrl/dom`, with only `@ctrl/dom` installed:

```ts
// vitest.config.ts
import { defineConfig } from "vitest/config";
import { ctrlDom } from "@ctrl/dom/vitest";

export default defineConfig({
  plugins: [ctrlDom()],
  // Optional and faster: each test file gets a fresh context in a reused worker instead of a
  // new worker, so per-file setup drops from about 23 ms to about 2 ms.
  test: { pool: "vmThreads" },
});
```

Vitest, DOM only (`pnpm add -D @ctrl/dom vitest-environment-ctrl-dom`):

```ts
export default defineConfig({ test: { environment: "ctrl-dom" } });
```

Jest (>= 30) (`pnpm add -D @ctrl/dom jest-environment-ctrl-dom`):

```js
// jest.config.js
module.exports = {
  preset: "@ctrl/dom", // whole stack: @testing-library/* routed to @ctrl/dom's CommonJS builds
  setupFilesAfterEnv: ["@ctrl/dom/jest-dom"],
  // testEnvironment: "ctrl-dom", // DOM only, stock @testing-library/*
};
```

Or import `@ctrl/dom/react`, `@ctrl/dom/user-event`, `@ctrl/dom/jest-dom`,
`@ctrl/dom/testing-library` and `@ctrl/dom/aria` directly. Node >= 26. Options, other runners
(node:test, Bun) and agent-friendly debug output are in the
[package README](publish/ctrl-dom/README.md).

## How it is fast

- **One internal node type.** Every node is backed by the same plain object shape (`NodeImpl`),
  so V8 keeps property access fast. jsdom puts a wrapper over an implementation object for each
  node and rebuilds its classes for every window; we share them.
- **Results are kept until the DOM changes.** Every mutation bumps a document version, and query
  results, accessible names, computed styles and live collections are reused until it changes.
- **Our queries read the DOM's data directly.** To find `getByRole('button', { name: 'Save' })`,
  stock Testing Library goes through every element on the page and calls DOM methods on each one
  to work out its role, its label and whether it's hidden. Ours is part of the DOM, so it reads
  the same information straight from the DOM's internal data. Same rules, same results, far less
  work.
- **Browser-engine shortcuts for selectors and CSS.** Selectors compile to matchers with id, class
  and tag shortcuts and an ancestor Bloom filter; style rules are bucketed and matched rules reused.
- **Timers don't wait.** The test environments run timers on a virtual clock that jumps ahead
  when nothing else is pending, so `findBy*`, `waitFor` and user-event delays cost microseconds.
